# Prompt 修改底层能力

## 1. 定位与边界

本文件是 Prompt 修改阶段的唯一核心能力源。它回答：

> 当目标变化、教学问题或参考效果已经明确后，当前 Prompt 为什么没有做到，以及怎样把所需教学动作或业务要求真正转成有效控制规则。

它负责：

- 理解用户真正要改变和保护什么；
- 重建当前 Prompt 的正向执行逻辑；
- 形成可解释的 Prompt 归因；
- 判断最小充分的修改范围；
- 将教学动作、用户要求或参考机制转译为 Prompt 控制；
- 交付可直接使用的局部修改或完整 Candidate。

它不重新定义什么是好的教学效果，不代替场景和教学动作资产作业务判断，也不把未测试的 Candidate 宣称为已经改善。

“完成本轮 Prompt 修改”与“验证版本有效”是两个完成条件：

- Candidate 已按要求形成，代表修改任务完成；
- Candidate 经实际测试和独立效果复核，才支持效果改善或版本接受结论。

## 2. 四种修改模式

由 `SKILL.md` 按用户已提供的判断选择直接局部修改、已知问题修复、参考能力迁移或结构建设，不把每次修改升级成完整诊断项目。

- 直接局部修改只需定位目标、检查关联冲突并保护变量和协议；
- 已知问题修复需要找到占优势的控制机制；
- 参考迁移把用户认可的效果作为设计依据，证据不足时只形成机制假设；
- 结构建设先确认场景职责、输入、边界、停点和产品契约。

各模式共享后续的正向增益、最小充分修改、控制归因和动作转译原则。

## 3. 第一原则：正向增益

Prompt 修改的目标不是让文本更长、更规范或理论上更完整，而是：

> 在尽可能保持当前 Prompt 已有有效能力和行为分布稳定的基础上，解决用户明确关注的问题。

每次修改同时存在两类对象：

```text
需要改变的能力
+
需要保护的能力
```

修改前至少在内部回答：

1. 本轮到底要改变什么；
2. 哪些能力、业务字段和产品协议不能被破坏；
3. 为解决问题最少需要影响哪些控制位置；
4. 最大的可预见回归是什么。

不要借当前任务顺便优化无关问题。少量、没有明显教学损失的残留可以保留。

## 4. 最小充分修改

“最小”不是字数最少或永远只改一段，而是：

> 为真正作用于问题根因，所需的最小控制范围。

修改范围从小到大依次考虑：

1. 单条规则或字段；
2. 补充一个必要判断或行为出口；
3. 联动多个相关规则；
4. 调整优先级、例外或规则关系；
5. 局部结构调整；
6. 整体重构。

只有前一层不足以解决根因时才扩大范围。若问题来自多条规则组合、缺失状态判断或刚性流程覆盖，改一个表面词不构成最小充分修改。

判断标准不是“改了多少字”，而是：

- 修改是否作用于主要控制因素；
- 是否保留了目标 Prompt 的有效能力；
- 是否引入了不必要的全局扰动；
- 是否存在更小且同样充分的方案。

## 5. 先理解 Prompt 如何正常运行

复杂问题不能只靠关键词搜索。先重建当前 Prompt 的正向执行路径：

```text
读取场景与输入
→ 确定本阶段目标、边界和停点
→ 判断必须处理的知识对象
→ 读取最近学生输入与累计证据
→ 判断当前进度和关键缺口
→ 选择下一步教学动作
→ 决定反馈、讲解、提问、步幅与结束
→ 应用轮次、格式和产品约束
→ 形成学生侧表达
```

这是一种归因抓手，不要求所有 Teacher Prompt 按此模板编写。根据任务复杂度选择理解深度：

- 局部低风险修改只检查目标段及其直接调用关系；
- 行为问题需要追踪影响该行为的所有关键规则；
- 结构问题才需要建立完整执行图。

归因时问：

> 如果模型忠实执行当前 Prompt，它为什么会合理地走到这个不理想出口？

## 6. 先判断问题来源

效果问题成立，不代表一定来自 Teacher Prompt。修改前检查当前证据是否更指向：

- 场景定义缺失或冲突；
- input 缺失、错误或与业务预期不一致；
- student simulator 异常；
- 测试流程或运行环境；
- Prompt 内容身份不确定；
- 单次随机波动。

已确认属于非 Prompt 来源时停止修改并指出应返回的环节。来源尚不确定时，可以给出待验证的 Prompt 假设和所需材料，但不能把防御性规则直接写入 Candidate。

直接局部修改由用户明确要求驱动，不需要先做效果来源认证；仍要检查该改动与相邻规则是否冲突。

## 7. Prompt 内部的四类控制根因

### 7.1 单条规则直接导致

一条规则本身稳定诱发目标行为。例如“每次回答后都先积极肯定”会使反馈与学生实际贡献脱节。

优先处理：局部改写触发条件、动作或边界。

### 7.2 缺少必要机制

已有规则本身未必错误，但缺少完成决策所需的状态、累计证据、停止条件或行为出口。

例如只规定“不知道时降难”，却没有区分第一次不知道与连续支架失败，容易造成无休止的同类低阶追问。

优先处理：补充最少的判断与切换机制。

### 7.3 多条规则组合形成错误出口

单条规则各自合理，组合后却把模型压缩到少数不理想行为。例如：

```text
每轮保持互动
+ 尽量不直接讲答案
+ 问题要简单
+ 每轮只完成一个动作
→ 持续制造低价值小问题
```

优先处理：调整规则关系、优先级、适用条件或例外，删除重复约束，并为模型恢复合理出口。

### 7.4 Prompt 结构使正确规则失效

正确原则可能被更具体的固定流程、重复硬约束、分散位置或大量低价值内容覆盖。

“Prompt 里已经写了”只能证明设计意图存在，不能证明它实际控制了输出。要找到真正占优势的规则，而不是再叠加一条同义原则。

优先处理：合并重复规则、把关键决策放回实际控制位置、明确优先级；只有局部调整不足时才重构。

## 8. 归因标准：可解释，不伪装成唯一证明

Prompt 是概率性的语言控制系统，通常无法像代码一样证明某一行必然导致某个输出。合格归因应给出可检查的机制链：

```text
相关规则或缺失机制
→ 模型可用行为范围如何变化
→ 哪个控制因素占优势
→ 为什么会形成当前表现
→ 为什么选择这些修改位置
```

至少说明：

- 哪些规则或模块参与；
- 主要控制因素是什么；
- 哪些判断仍是假设；
- 为什么暂不修改其他部分。

不要把相关性写成已经证明的唯一因果。需要更强归因时，用固定关键学生回复、受控变量或 Baseline/Candidate 回归验证。

## 9. 将教学动作转译为 Prompt 控制

上游往往给出“Teacher 应该怎么做”，Prompt 修改还要回答“模型需要知道什么才能稳定做到”。

把教学动作拆成五个控制元素：

```text
触发条件
+ 判断对象
+ 目标动作
+ 动作边界
+ 必要优先级
```

例如，上游判断是“学生连续不知道时，停止继续索取答案，改为直接讲解或重建入口”。可转译为：

```text
连续失败证据
→ 判断当前入口或支架失效
→ 停止重复同难度、同类型索取
→ 切换为解释关键关系、补充前置或更换入口
→ 学生重新获得理解入口后再推进
```

Prompt 中保留的是控制逻辑，不是固定句式。具体写法由当前场景、学科、Prompt 架构和用户要求决定。

### 9.1 先控制判断，再控制动作和表达

优先顺序是：

```text
学生证据与当前缺口
→ 需要的教学功能
→ 下一步动作
→ 学生侧表达
```

反馈、提问和讲解首先是教学功能，不是话术模板。能够通过状态判断和动作选择解决的问题，不优先通过禁词、同义句或固定问式解决。

### 9.2 正向规则优先

先写 Teacher 应如何判断并做对，再用少量禁止项守住知识错误、明确越界、答案泄露、内部术语外露等底线。

无限增加“不要、避免、禁止”会造成规则膨胀、注意力稀释和行为出口减少。

### 9.3 控制关系，不机械绑定单位

知识字段、知识关系、学生证据、教学动作、问题和轮次不是固定一一对应。不要让每个字段自动变成一次播报或抽查，也不要把每项学生证据都机械映射成一个问题。

关系组织可以保留；反馈、提问和步幅只服务当前最关键的理解缺口。

## 10. 参考 Prompt 的能力迁移

参考 Prompt 只提供用户认可效果的可能机制，不替代目标 Prompt。遇到参考版本、跨 Prompt 借鉴或跨学科迁移时，读取[参考 Prompt 能力迁移](../20_条件能力/10_参考Prompt能力迁移.md)，建立“参考效果—参考机制—目标保护项—迁移边界—目标控制点—回归风险”的完整映射。

普通局部修复不加载该文件，也不为当前任务寻找无关参考 Prompt。

## 11. Prompt 架构与规则放置

架构服务控制，不是固定模板。普通修改只定位目标机制的实际控制位置；新场景或确需结构重构时，再读取[场景资产建设与 Prompt 工程说明](../20_条件能力/00_场景资产建设与Prompt工程说明.md)检查整体覆盖。

修改时把规则放到真正控制该行为的位置：

- 场景和停点问题进入场景职责；
- 覆盖与编造问题进入输入和知识边界；
- 状态不改变动作的问题进入学生输入与决策；
- 固定问式问题进入提问功能和触发条件；
- 结束轮问题进入轮次和产品契约。

不要把同一能力分散重复在多个章节，也不要把完整效果标签、评分表、历史 badcase 或其他学科规则塞进 Teacher Prompt。

## 12. 长度、示例与注意力

### 12.1 主 Prompt 只保留执行所需控制变量

优先保留场景职责、知识边界、教学主线、学生输入决策、必要互动原则、轮次契约和少量底线。完整分析框架留在优化 Skill，不转移给 Teacher。

### 12.2 示例展示决策，不只展示句式

示例应说明适用状态和教学功能；数量保持必要，不让模型围绕少数形式过拟合。测试 Case 不直接写入 Prompt，应先提炼控制机制。

### 12.3 删除重复比追加同义规则更优先

已有规则未生效时，先检查优先级、冲突、位置和刚性流程。重复添加同义要求通常只会加剧注意力竞争。

## 13. 常见过修复

- 为消除选择题，强迫所有问题开放，导致问题过难；
- 为避免自问自答，删除所有提问，导致无法读取学生状态；
- 为防止跑题，禁止必要解释，导致讲解干瘪；
- 为提升温度，堆叠语气词和夸奖，导致低幼或表演化；
- 为控制长度，压缩输入中的核心知识；
- 为制造多样性，轮换句式但不改变认知动作；
- 为守住问句结尾，在答案已经给出后强行补问；
- 为一个边缘 Case 增加全局重规则；
- 为借鉴参考效果，覆盖目标学科、输入或输出协议；
- 为让结构更漂亮，重写已经稳定有效的无关模块。

发现这类风险时，回到“目标变化—保护项—最小充分范围”，而不是再增加一层补丁。

## 14. 何时允许重构

重构必须由控制证据驱动，例如多类问题共同指向同一上游结构，或局部调整始终无法让学生状态改变下一步。需要扩大到结构层时，读取[场景资产建设与 Prompt 工程说明](../20_条件能力/00_场景资产建设与Prompt工程说明.md)；仍要优先保留场景事实、变量、输入边界、输出协议和已验证有效的专属能力。

## 15. 修改后的快速检查

按任务相关性检查，不机械输出清单：

### 15.1 目标与范围

- 本轮变化是否直接对应用户目标；
- 是否修改了无关模块；
- 是否存在更小但同样充分的范围。

### 15.2 控制机制

- 触发条件、判断对象、动作、边界和优先级是否清楚；
- 是否处理了真正占优势的规则；
- 是否只是替换表面词语或模板。

### 15.3 保护能力

- 场景职责、知识边界和停点是否保留；
- 变量、输入字段、输出格式、标签和控制信号是否完整；
- 目标学科和模块的专属规则是否被参考 Prompt 覆盖。

### 15.4 注意力与冲突

- 是否重复添加已有能力；
- 是否新增明显冲突或无限禁止项；
- 是否把分析框架错误写进 Teacher Prompt。

### 15.5 可验证性

- 修改位置和改善假设是否能对应；
- 原问题、相邻 Case、历史保护 Case 和高风险回归点是否可被测试。

## 16. 交付与共创边界

用户要求完整 Prompt 或需要可直接替换测试的版本时，交付完整 Markdown Prompt，并保留所有必要变量与协议。用户只要求局部修改、差异或方案时，按其要求交付，不主动扩大为全量重写。

只有以下情况需要继续对齐：

- 问题仍模糊，无法决定修改方向；
- 多个根因会产生实质不同的方案；
- 所需范围明显超过用户要求；
- 存在会改变业务取舍的效果冲突；
- 缺少无法安全推断的场景、输入或产品契约。

用户已经明确“按这个方向修改”时，不再设置机械审批门。AI 完成必要归因、转译、冲突检查和交付；用户、PM 或 Owner 决定是否测试、接受、回退或写入长期资产。
