# 一对一教学 Case 审查调用协议 v0.2

## 协议定位

这是当前两层体系中的第二层，也是使用层。

第一层[《寒雪一对一教学效果底层认知模型 v0.5》](../00_效果判断核心/00_寒雪一对一教学效果底层认知模型_v0.5.md)保存“如何理解一对一教学”的判断力；本协议只说明如何把具体 case 交给模型，并获得自然、具体、可复核的分析结果。

本协议不会重新定义教学效果，也不会要求 Agent 填写固定表格、输出全部字段或使用统一编码。数据格式、报告篇幅和交付习惯可以变化，底层判断标准不能由调用形式反向改写。

本协议结束于效果问题被清楚定义。它不读取 Prompt 来反推问题，也不生成 Prompt 修改方案。

---

## 一、一次调用要回答什么

无论输入一个 case 还是一批数据，调用的核心目的都是：

> 依据底层认知模型，判断当前 Teacher 输出中的教学关系是否成立；如果不成立，用人能理解的语言说明学生处于什么状态、Teacher 偏离在哪里、造成了什么影响，并明确当前证据最多支持多大的结论。

好的调用结果不以报告长度、字段数量或标签完整度衡量，而以三件事衡量：

- 问题是否具体到能够被讨论和裁决；
- 判断是否能回到原始 case 证据；
- 结论是否没有越过场景和数据允许的范围。

---

## 二、怎样提供 case

协议不要求使用者先填写一张完整的 Case 表。存在可读的教学内容时通常就可以开始审查；材料越完整，模型能够判断的范围越大。

最有价值的材料通常包括：

- 原始学生与 Teacher 对话，尽量保留完整轮次和原话；
- 当前学科、学段、教学模块或任务说明；
- 当前场景已有的具体规则；
- 题目、课文、标准知识、结构化输入或其他内容依据；
- 当前轮次在完整教学中的位置、已知的结束要求，以及实际的继续/结束控制信号；
- 如果涉及对照，说明哪些输出属于哪个版本或运行条件；
- 已经明确的用户或 Owner 裁决。

这些不是必须预先填齐的字段。缺少某项材料时，Agent 应缩小结论：先完成仍然能够成立的局部判断，再说明哪些部分无法确认；不应凭通用经验补写缺失事实。如果场景、目标、知识依据和有效对话同时不足，连局部判断也无法可靠成立，可以明确说明当前整体不可判定。

原始数据应尽量保持原貌。学生的口误、反复、不知道、偏题和异常表达本身都可能是教学证据，不要先替 Agent 清理成标准答案。

---

## 三、模型如何进入 case

本协议不要求把内部思考按步骤全部展示，但三条判断依赖不能被颠倒：

1. 不知道当前场景要完成什么，就不能准确评价 Teacher 的动作；
2. 没有理解学生已经做到什么、还缺什么，就不能准确评价下一步是否合适；
3. 效果问题还没有定义清楚，就不能进入 Prompt 根因判断。

Agent 在阅读 case 时，应把整段对话看成一个动态教学关系，而不是逐句寻找违规词：

- 学生原话提供了什么信息；
- Teacher 如何理解这些信息；
- Teacher 的下一步是否因此发生了合理变化；
- 这段变化是否服务当前目标；
- 后续轨迹是否支持、修正或限制了当轮判断。

分析不寻找唯一理想回复。只要 Teacher 的动作处于当前场景允许、学生能够承接、并能作用于关键缺口的合理范围内，就可以成立。

## 四、怎样表达审查结果

审查结果首先要让人看懂，再考虑是否需要表格、标签或索引。

面对有问题的 case，通常需要让读者自然理解：

- 学生已经会了什么、还差什么；
- Teacher 实际做了什么；
- 最关键的偏离发生在哪一句或哪一轮；
- 为什么这会影响当前教学；
- 在当时条件下，什么样的教学动作更合理；
- 当前输出中有哪些已经成立、需要保留的能力；
- 哪些资料缺失，使结论暂时不能扩大。

这些内容可以合并成一段，也可以按 case 复杂度拆开。没有问题时，不需要为了完成模板虚构缺口；证据不足时，也不需要勉强给出严重度。

### 推荐的问题表达

> 学生已经能够说出人物的基本特点，但还没有找到文本依据。Teacher 没有沿着这个缺口继续帮助学生定位证据，而是直接切换到全文结构，导致当前细读尚未闭环便更换了知识对象。

这类表达同时包含学生状态、合理目标、Teacher 动作和教学影响。

### 不足以构成分析的表达

- “效果不够好”；
- “互动不足”；
- “教学推进一般”；
- “不够自然”；
- 只给内部编号或严重度，不解释具体发生了什么；
- 只改写一版更好的 Teacher 回复，不先定义原问题。

### 证据怎样出现

重要判断应尽量引用最短、最关键的学生或 Teacher 原话，并指出所在 case 或轮次。引用的作用是让判断可复核，而不是大段复制全部对话。

同一处偏离产生多个下游表现时，优先说明最能解释主要损失的上游断裂。只有另一个表现造成了独立教学损失，才单独列为第二个问题。

## 五、单个 case 的调用方式

可以直接使用以下指令：

```text
请加载《一对一教学效果底层认知模型》，并在当前场景已有具体规则时一并加载，审查下面这个一对一教学 case。若没有对应场景规则，请明确场景规则缺口，只按通用关系和当前证据完成有边界的判断。

本轮只判断教学效果，不分析或修改 Prompt。请先完整理解场景和对话，再用自然语言说明：这段教学在当前可评范围内是否成立；如果有问题，学生已经处于什么位置、此刻真正需要什么、Teacher 实际做了什么、为什么损害了教学关系或学习机会，并引用最关键的原文证据。同时指出已经有效的能力，以及当前资料不能确认的部分。

不要寻找唯一标准回复，不要用表面词频、问号、字数或固定题型直接判定问题，也不要为了套模板输出与本 case 无关的栏目。
```

如果使用者已经怀疑某个问题，可以追加：

```text
我当前怀疑的问题是：……。请把它作为待验证假设，不要预设它一定成立；如果真正的问题不同，请依据 case 说明。
```

这样既允许用户提出新问题，也不会让 Agent 为了迎合假设而扭曲证据。

## 六、批量 case 的调用方式

批量审查的关键不是增加一套复杂流程，而是守住一个顺序关系：先看懂每一个 case，再讨论重复模式。

可以直接使用以下指令：

```text
请加载《一对一教学效果底层认知模型》，并在各 case 有对应场景规则时一并加载，完整审查本次提供的全部 case。没有对应场景规则时，请明确场景规则缺口。本轮只进行教学效果评判，不进入 Prompt 归因或修改。

请为每个 case 说明当前能够确认什么、不能确认什么；整体可以基本成立、存在具体问题或总体证据不足，也可以在确认局部问题的同时保留其他关系无法判断的边界。问题必须用自然语言说明学生状态、Teacher 偏离和教学影响，并引用关键证据；没有明显问题时，说明已经成立的主要能力。

完成逐案判断后，再汇总重复问题、明确的单 case 问题、好 case、反例和数据异常。不要根据前几条推断整批结果，不要把相似句式直接当成同一种问题，不要用词频或总分替代教学判断。
```

### 批量汇总应当回答的核心问题

一份有用的批量结果通常能让人看清：

- 这批输出整体最值得关注的教学损失是什么；
- 哪些问题在相似条件下重复出现，涉及哪些 case；
- 哪些只是独立但重要的单 case 问题；
- 哪些 case 明确成立，可以作为保护样本或反例；
- 哪些结论受原始材料缺失、轮次丢失或场景不明限制。

呈现形式可以是一页结论、问题专题加 case 索引，或逐案短评加汇总，不要求固定结构。

### 频率和占比怎样使用

频率只能建立在已经完成的教学判断上，不能先搜索“你觉得”“没错”或问号再把命中次数当成问题次数。

分母应尽量是该问题真正有机会发生的 case。例如，判断“学生不知道后没有降难”，分母应是学生明确不知道或连续失败的 case，而不是整个数据集。

聚合时需要保留反例：如果相似表达在某些 case 中承担了有效功能，就要说明为什么这里成立、那里不成立。反例是证明模型拥有条件判断力的重要证据。

## 七、证据边界

调用时始终保留以下边界：

- 单个 case 直接支持的是单 case 结论；
- 多个相似 case 可以支持“本数据集中的重复模式”，不能直接证明 Prompt 存在系统性根因；
- 缺少知识材料时，可以判断明显的学生承接、提问或推进问题，知识覆盖和内容边界只能局部评价；
- 后续学生回答可以作为轨迹证据，不能改变 Teacher 当时可见的信息；
- 数据缺轮、解析错位或学生模拟器异常，应作为证据问题单独说明，不与 Teacher 教学问题混合；
- Prompt 版本名存在但无法确认唯一内容身份时，可以审查具体输出，不能形成可靠的版本结论；
- 两版初始输入相同但后续学生轨迹不同，只能直接支持效果差异比较，不能据此完成严格的 Prompt 条款因果归因；
- Teacher 文本是否合理推进或收束，与 `nextRound` 或同类控制信号是否正确是两个判断对象；缺少控制字段时可以评价文本停点，不能声称产品控制已经正确；
- 用户或 Owner 的裁决可以改变最终业务结论，但应与 Agent 的 case 分析依据保持可区分；
- 问题影响、问题来源和是否值得进入下一阶段，是不同判断，不能压成一个分数。

当资料不足但仍有关系可评时，应说明当前可以确认什么、不能确认什么，以及缺失信息为什么会改变判断。如果连局部关系所需条件也不存在，“当前整体不可判定”就是合法结论，但必须准确说明缺少什么。

---

## 八、协议的完成标准

一次调用完成，不是因为所有栏目都被填写，而是因为使用者已经能够回答：

- 当前最重要的问题是什么；
- 这个问题为什么成立；
- 证据在哪里；
- 它影响了哪一段教学关系；
- 哪些能力仍然成立；
- 结论目前适用于一个 case、一段会话，还是本数据集中的重复模式。

如果这些问题已经清楚，就不应继续增加字段、标签或审计步骤来制造形式上的完整。
