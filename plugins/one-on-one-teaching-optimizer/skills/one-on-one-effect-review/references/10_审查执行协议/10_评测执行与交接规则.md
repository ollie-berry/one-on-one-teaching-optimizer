# 评测执行与交接规则

## 1. 评测执行原则

1. 不先计算分数。评测的首要任务是识别具体问题、定位证据、判断影响和明确证据边界。
2. 不使用“效果不好”“不自然”“互动不足”“需要优化”等模糊结论代替分析。
3. 每个核心判断都应落到具体轮次、输出片段和被破坏的教学动作。
4. 先判断知识、边界和阶段职责，再判断话术、风格和表达自然度。
5. 先把教学效果问题定义清楚，再把来源归因和 Prompt 修改交给后续对应能力。
6. 不为少量局部现象牺牲跨 case 稳定性。
## 2. 确认当前阶段应该完成什么

从当前场景规则和本轮目标中判断：

- 当前阶段的核心职责是什么；
- 学生经过这一阶段应获得什么；
- teacher 允许做什么；
- teacher 禁止做什么；
- 输出到什么程度应停止。

如果没有对应场景规则，优化 Agent 只能按全局原则和用户提供的业务材料做有边界判断，并明确规则缺口；不能借用其他场景补写标准。

## 3. 定位被破坏的教学动作

不要只看表面话术，要判断它破坏了哪个教学动作。

常见教学动作包括：

- 阶段任务完成；
- 概念或内容讲解；
- 学生理解推进；
- 提问互动；
- 学生输入反馈；
- 内容边界控制；
- 学生侧表达。
## 4. 交接后续环节

效果评定完成后，只交接当前证据支持的材料，不在本文件中执行来源归因、Prompt 修改或版本批准：

- 已定义的效果问题、关键证据和教学损失；
- 仍然成立、需要保护的能力；
- 资料异常、场景规则缺口和其他会限制结论的条件；
- 需要更多 Case 才能确认的观察项；
- 若用户要求继续优化，交给 Prompt 修改 Skill 判断来源和形成 Candidate；
- 若用户要求比较版本，连同两版实际输出交给独立效果复核和后续版本建议环节。

## 5. 评测顺序

评测任何版本时，按以下顺序：

1. 知识准确与内容边界；
2. 阶段职责与停点；
3. 教学推进路径；
4. 学生输入承接；
5. 互动与提问质量；
6. 表达自然度；
7. 跨 case 稳定性。

不能先看语气是否好听，再判断教学是否成立。
## 6. 分析时

- 先进入具体场景，再判断输出；
- 先找教学失败点，再评价文风；
- 先把效果问题与资料异常分开，不在本阶段反推 Prompt 根因；
- 所有重要结论绑定具体 case；
- 对不确定判断明确缺少的证据或规则；
- 不将本学科规则直接泛化到其他学科。
