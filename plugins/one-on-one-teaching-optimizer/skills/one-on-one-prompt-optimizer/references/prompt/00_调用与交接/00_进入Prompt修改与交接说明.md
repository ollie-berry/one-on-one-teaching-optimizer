## 1. 文档定位与使用前提

本文件用于在教学效果问题已经被确认后，将“教学失败”定位到 Prompt 的控制机制，并选择最小有效修改、结构性重构或不修改。

进入 Prompt 修改前，至少应确认：

- 当前学科、学段、模块和教学阶段；
- 当前模块的职责、边界和停点；
- badcase 中可观察的问题证据；
- 被破坏的教学动作；
- 问题是否确实来自 Teacher Prompt；
- 本轮优化目标和需要重点观察的回归风险。

不得因为某个输出不理想，就跳过上述判断直接重写 Prompt。
### 7.1 先确认场景与业务边界

- 入参是否固定；
- 哪些内容必须讲；
- 模块在产品链路中的位置；
- 轮次字段含义；
- 哪些问题不由 Prompt 兜底。

### 7.2 基于 case 识别教学失败点

不要只说“模板化”“互动不足”，要说明：

- 出现在什么轮次；
- 问题主体是什么；
- 破坏了哪个教学动作；
- 学生因此无法完成什么。
### 7.7 决定继续优化、收口或回退

版本收口不是追求零瑕疵，而是判断核心问题是否稳定解决、剩余风险是否可控、继续修改是否收益大于回归风险。
