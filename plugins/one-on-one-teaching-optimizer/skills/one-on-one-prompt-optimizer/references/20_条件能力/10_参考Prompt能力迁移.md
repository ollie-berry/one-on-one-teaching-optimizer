# 参考 Prompt 能力迁移

## 1. 使用条件

仅在用户明确提供另一 Prompt、历史版本或 Case 作为效果参考，或要求进行跨 Prompt、跨版本、跨学科能力迁移时读取。

开始至少确认：

- 目标 Prompt 的准确内容和适用场景；
- 参考 Prompt 或参考输出的准确内容；
- 用户真正希望获得的目标效果；
- 目标 Prompt 必须保留的能力、字段和产品契约。

有可比 Case 时，先继承已经确认的效果 Gap。只有 Prompt 文本或用户评价时，可以分析可能机制并形成待验证 Candidate，但不能把参考机制写成已经证明的唯一因果。

## 2. 迁移不是文本拼接

参考 Prompt 只承担“提供目标效果的可能逻辑来源”，不取得对目标 Prompt 的整体优先级。

```text
目标 Prompt 原有有效能力
+ 参考 Prompt 中需要的控制逻辑
→ 目标场景适配后的 Candidate
```

不是：

```text
参考 Prompt
→ 覆盖目标 Prompt
```

## 3. 迁移映射

修改前建立以下映射，不要求机械输出表格，但每项判断应能回到材料：

| 判断对象 | 需要回答的问题 |
|---|---|
| 参考效果 | 用户认可的可观察变化究竟是什么 |
| 参考机制 | 哪些规则、优先级或结构可能产生该变化 |
| 目标现状 | 目标 Prompt 为什么没有稳定形成同类能力 |
| 目标保护项 | 哪些已有能力、字段、学科规则和协议必须保留 |
| 可迁移内容 | 哪些通用教学决策适用于目标场景 |
| 不迁移内容 | 哪些只是表面形式或参考场景专属规则 |
| 目标控制点 | 迁移机制应进入目标 Prompt 的哪个实际决策位置 |
| 回归风险 | 融合后最可能损伤什么 |

## 4. 从效果 Gap 到机制 Gap

先具体说明两者在教学关系上的差异，再寻找可能控制该差异的规则。

例如，参考版本的反馈会随学生证据变化，连续正确后不再做同层确认；目标版本对不同学生状态仍走相似的“肯定—提问”流程。要迁移的是：

- 学生状态和累计证据进入下一步决策；
- 反馈功能与学生真实贡献对应；
- 已有充分理解证据时允许直接推进。

不是复制参考版本的肯定句或问句。

归因遵循 Prompt 修改核心：重建参考 Prompt 的正向执行逻辑，找到最有解释力的控制机制，并区分文本线索、Case 证据和用户判断的证据等级。

## 5. 迁移边界

更适合迁移：

- 学生状态和累计证据的处理逻辑；
- 教学动作选择；
- 节奏、步幅和停点判断；
- 提问、反馈和讲解的功能；
- 规则关系、优先级和行为出口。

不宜机械迁移：

- 固定话术和固定问句；
- 固定轮数；
- 固定知识拆分或内容组织形式；
- 参考学科专属的内容、深度、错误类型和支架；
- 参考 Prompt 的变量、输入字段、输出格式和产品协议。

跨学科时还要读取公共的跨学科迁移边界。只迁移能够在目标场景中重新解释的决策原则，不把一个学科的表面成功模式升级成通用标准。

## 6. 融入目标 Prompt

1. 先检查目标 Prompt 是否已经有同类原则；
2. 若已有但未生效，处理覆盖它的刚性流程、优先级或规则组合，不重复添加同义规则；
3. 找到目标 Prompt 中真正控制该行为的位置；
4. 用目标场景的知识对象、学生状态和产品契约重写机制；
5. 只联动为使机制生效所必要的相关模块；
6. 保留目标 Prompt 的专属结构和已经有效的能力。

形成 Candidate 时，能够对应说明：

```text
参考机制
→ 目标控制点
→ Candidate 中的具体变化
→ 预期教学动作变化
→ 需要保护和验证的风险
```

## 7. 交付与验证

用户要求完整版本时，交付目标 Prompt 的完整可替换 Candidate，而不是参考 Prompt 的改名副本。保留目标版本的变量、输入字段、输出格式、标签协议和未受影响规则。

验证至少区分：

- 参考效果是否已由可比输出观察到；
- 参考机制是否只是当前最有解释力的设计假设；
- Candidate 是否在目标场景中产生了预期教学动作；
- 目标 Prompt 原有有效能力是否被保留；
- 是否出现跨学科误迁移、轮次膨胀、知识漏讲或新模板。

没有目标场景的 Candidate 测试时，只能说明迁移设计和 Prompt 修改已经完成，不能声称能力已经稳定继承。
