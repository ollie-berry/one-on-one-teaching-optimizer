# 教学效果判别能力
### 5.6 不为局部 case 牺牲全局稳定性

当一个问题只出现在少数边界 case 中，优化 Agent 必须先判断它是否值得进入 prompt 修复。

不得为了清理一个轻微问题而导致：

- 讲解变干瘪；
- 完全没有互动；
- 问题变得过难或不自然；
- 原有有效能力被破坏；
- prompt 中堆入大量零散禁止项。
### 7.7 版本稳定性，P2

#### 要判断什么

- 新版是否稳定解决原核心问题；
- 是否只在少数 case 上变好；
- 是否引入新系统性问题；
- 是否只是表层话术变化；
- 是否为了解决局部问题造成过修复。

#### 高风险表现

- 为避免自问自答，导致完全没有互动；
- 为避免跑题，导致讲解过于干瘪；
- 为提升人感，导致知识不严谨；
- 为问题结尾，制造大量模板化尾问；
- 为压缩长度，导致教学推进断裂；
- 针对测试集表面特征过拟合。
### 8.7 规则优先级冲突

prompt 为满足某个低优先级目标，破坏了更高优先级目标。

例如：为了人感牺牲准确性，为了互动制造伪问题，为了防跑题导致讲解过于干瘪。

### 8.8 过修复

为解决局部问题而引入更大的系统性问题。

例如：为了消除所有选择式问题，导致提问过难；为了避免自问自答，导致完全没有互动；为了控制长度，导致教学推进断裂。
## 11. 最终判断原则

### 11.1 判断 Prompt 是否有效

一个 prompt 是否有效，不取决于它是否更长、更复杂、问题更多、语气更热情，而取决于它是否让 teacher 在真实一对一教学中更稳定地做到：

1. 知道当前阶段该做什么；
2. 知道讲到哪里该停；
3. 能围绕学生理解路径推进；
4. 能提出真正服务教学的问题；
5. 能接住学生输入；
6. 能避免知识错误、编造、跑题和内部术语外露；
7. 能保持自然、可信、有老师感；
8. 能在不同 case 中保持稳定，不为局部问题过修复。

### 11.2 判断一个版本是否值得接受

一个 teacher prompt 是否值得接受，不取决于它是否更长、更复杂、更生动，而取决于它是否让 AI 老师在真实一对一教学中更稳定地做到：

1. 当前阶段做对；
2. 教学边界守住；
3. 学生能跟上；
4. 问题有教学功能；
5. 学生输入被接住；
6. 表达自然可信；
7. 历史判断能够被继承。

每一轮优化都要回答四个问题：

1. 当前版本是否真的变好；
2. 为什么变好或没变好；
3. 哪些判断以后要继承；
4. 哪些问题不能再被误判或重复踩坑。
