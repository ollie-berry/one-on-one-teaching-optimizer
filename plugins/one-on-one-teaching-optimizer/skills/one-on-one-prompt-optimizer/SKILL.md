# 一对一教学 Prompt 修改

本 Skill 承接已经明确的教学效果问题，将其定位到 Teacher Prompt 的控制机制，形成有依据的最小有效修改，并设计修改后的回归验证。

## 职责边界

本 Skill 负责：

- 判断已明确的效果问题是否确实由 Teacher Prompt 导致；
- 定位造成问题的规则、结构、优先级、固定流程或规则组合；
- 区分规则缺失、规则模糊、规则冲突、规则过强和实际控制失效；
- 选择局部修改、结构调整、重构或暂不修改；
- 按用户需要生成 Candidate Prompt、差异修改或修改方案；
- 设计 Baseline / Candidate 的验证范围和回归风险；
- 根据效果复核结果决定接受、继续优化或回退。

本 Skill 不负责从原始 Case 中首次发现教学效果问题，也不重新定义学生状态、教学失败点或效果标准。不要在没有效果证据时直接重写 Prompt，不自行确权尚未确认的业务边界，不自行声称 Candidate 已改善实际教学效果。

原始 Case 审查和修改后的实际效果复核交给 `$one-on-one-effect-review`。

## 进入条件

开始归因前，必须已有足够明确的效果问题定义。它可以来自 `$one-on-one-effect-review`，也可以由用户或 Owner 明确给出。

问题定义应足以看清：

- 问题发生在哪个学科、学段、模块和教学阶段；
- Case 中可以观察到的具体证据；
- Teacher 实际破坏了什么教学动作；
- 它给学生理解或教学链路造成了什么影响；
- 哪些部分已经确认，哪些仍不确定。

这些是判断所需信息，不要求用户填写固定表格。若只有“效果不好”“互动不足”“太模板化”等笼统感受，停止 Prompt 修改，先交给 `$one-on-one-effect-review` 定义问题。

开始修改还需要当前 Teacher Prompt 的准确内容、相关业务输入和 Case、已经确认的场景职责与边界，以及用户或 Owner 的本轮目标。关键材料缺失时，说明缺口及它会影响的判断，不臆造内容。

## 归因与修改

先确认问题来源。效果问题已经成立，不代表它一定来自 Teacher Prompt。检查场景定义、业务输入、学生模拟器、测试流程、运行环境、Prompt 版本身份和单次随机波动是否可能造成当前表现。

依据不足时，明确还需要什么；确认属于非 Prompt 来源时停止修改，并指出应返回哪个环节处理。

确认 Prompt 来源后，定位真正占优势的控制机制。Prompt 中已有正确原则，不等于该原则实际控制了输出；继续检查是否有更强的固定流程、硬约束、规则优先级或规则组合覆盖它。

修改时：

- 先处理结构根因，再考虑局部措辞；
- 优先采用能够解决根因的最小修改；
- 保留原版本已经有效的能力；
- 不把完整效果评定框架塞进 Teacher Prompt；
- 不用大量禁止项修复单个 Case；
- 不把一个场景的规则机械推广到其他学科或模块；
- 不通过删除全部互动、补充或选择式问题等方式过修复；
- 只有当前架构持续产生多类系统性问题时才建议重构。

涉及教学深度、知识来源、结束轮、产品字段或其他未确权边界时，提出具体分歧，等待用户或 Owner 裁决，不自行写死。

## 回归设计与交接

Candidate 形成后，设计与修改假设相对应的验证：

- 原问题 Case 检查目标问题；
- 相邻 Case 检查同一机制是否稳定；
- 历史有效 Case 检查原有能力是否保留；
- 高风险场景检查知识、边界、互动、表达和跨场景回归。

版本比较前，核对 Baseline 与 Candidate 的准确 Prompt 内容，以及会实质影响结果的输入集、Teacher 模型、student simulator、场景规则、运行条件和控制信息。条件不完整时可以描述可观察比较，但不能扩大因果结论。

测试次数、样本规模、通过阈值和显著性标准必须沿用用户、Owner 或业务已经确认的设置。当前资料没有规定时，可以把它们列为待确定的执行参数，或明确标注为本轮建议；不能写成项目既有硬规则。

将以下材料交给 `$one-on-one-effect-review`：

- 已确认的原效果问题及 Case 证据；
- Baseline 和 Candidate 的准确 Prompt 内容；
- 本次修改位置、控制机制和改善假设；
- 目标 Case、相邻 Case 和需要保护的历史能力；
- 适用场景规则和必要运行条件；
- 重点观察的回归风险；
- 已生成的两版测试输出，如已有。

由效果评定 Skill 独立审查两版教学效果。没有复核结果时，只能说明已形成 Candidate 和回归方案，不能声称效果已经改善。收到复核结果后，再决定接受、继续优化或回退。

## 输出

根据用户当前需要，提供足以支持决策的内容，包括已承接的问题与证据边界、来源判断、Prompt 控制根因、建议修改及理由、Candidate 或差异方案、被保护的原有能力、回归风险、复核范围和仍需确权的事项。

不强制固定报告模板，但每个关键结论必须能够回到当前问题、Prompt 内容或 Case 证据。
