# Baseline-Candidate 版本对照

## 1. 同输入多版本的调用方式

当同一输入存在多个 Teacher 版本时，可以让模型分别理解每个版本，再比较教学关系发生了什么变化。

比较前应先确认两版各自唯一的 Prompt 内容，以及输入集、Teacher 模型、student simulator、场景与规则版本、关键运行条件和输出控制信息。版本名相同不代表 Prompt 内容相同；无法确认内容身份或关键条件时，可以描述可观察差异，但不能把结果合并成一个稳定版本结论。

```text
请使用同一份《一对一教学效果底层认知模型》和同一套适用场景规则，分别审查 Baseline 与 Candidate。先独立判断两版教学效果，再比较：原问题是否真正改善；改善发生在什么教学关系上；原本有效的能力是否保留；是否出现新的、更高优先级的损失。

请同时核对两版的唯一 Prompt 内容、输入集、Teacher 模型、student simulator、场景与规则版本、关键运行条件和输出控制信息。不要只比较字数、句式或问句数量。关键条件不一致、无法确认或材料缺失时，请说明可比范围并缩小比较结论。
```

多轮教学中，Teacher 输出变化可能继续改变 student simulator 的回答，所以“同一初始输入”不自动产生“同一学生轨迹”。这种对照首先支持的是两版形成了什么不同的可观察教学关系，不自动证明 Candidate 的变化由某一条 Prompt 修改造成。若要判断具体控制机制，应尽量固定关键学生回复，或至少保留完整对话轨迹与运行条件。
