# Prompt 诊断与修改能力
## 1. 效果问题对应的常见 Prompt 根因

### 1.1 知识准确与内容边界

#### 常见 Prompt 根因

- 没有限定信息来源；
- “生动、有趣、丰富”的要求高于边界约束；
- 没有定义当前阶段的输出停点；
- 没有区分当前任务和后续任务。

### 1.2 阶段职责匹配

#### 常见 Prompt 根因

- 阶段目标只写“讲什么”，没写“讲到哪里停”；
- 未定义本阶段允许和禁止的教学动作；
- 多个目标并列，缺少优先级；
- 场景定义缺失或没有被正确引用。

### 1.3 教学推进有效性

#### 常见 Prompt 根因

- prompt 只要求“讲清楚”，没有定义教学路径；
- 缺少“一轮只解决一个核心问题”的约束；
- 为了完整性牺牲了学生理解节奏。

### 1.4 学生输入承接

#### 常见 Prompt 根因

- prompt 没有要求每轮先处理最近的 student input；
- 讲解路径被写成固定脚本；
- 没有定义学生答错、不知道、部分正确时的最小处理动作。

### 1.5 互动与提问质量

#### 常见 Prompt 根因

- 只规定“要提问”，没有定义有效问题；
- 没有区分真实互动问题和讲解过渡设问；
- 非结尾轮必须提问，但缺少可用问题类型；
- 没有限制“已经讲出答案后再问同一答案”。

### 1.6 表达自然度与一对一老师感

#### 常见 Prompt 根因

- prompt 中内部理解语言没有与学生侧输出隔离；
- 只要求“自然”，没有定义需要避免的机器感模式；
- 示例话术过于模板化。

## 2. Prompt 的推荐层级结构

一个稳定的一对一教学 Prompt 通常应包含以下层级，顺序体现优先级：

### 2.1 角色与对象

定义老师身份、学生年级和总体语气。该部分应简洁，不承担教学流程细节。

### 2.2 场景职责

明确：

- 当前模块处于整个教学链路中的位置；
- 核心任务；
- 前置状态；
- 停点；
- 与相邻模块的边界。

这是 Prompt 中最关键的部分之一。

### 2.3 输入与知识边界

说明：

- 哪些输入必须完整覆盖；
- 是否允许补充；
- 不确定信息如何处理；
- 禁止编造和无关扩展。

### 2.4 教学推进原则

定义理解路径，而不是固定台词。例如：

- 从具体材料进入；
- 一轮聚焦一个核心动作；
- 先观察再归纳；
- 讲解与提问围绕同一知识主线；
- 完成当前目标后及时停止。

### 2.5 学生输入处理

只保留高价值决策原则，不要塞入完整评测分类表。

建议写法：

- 每轮先判断最近学生输入；
- 正确则具体确认并推进；
- 部分正确则保留有效部分并补足；
- 错误则温和纠偏；
- 不知道则降难或给提示；
- 已答出目标则不重复追问。

### 2.6 提问与互动

定义有效问题标准、问题功能和禁区，不要求模型机械轮换固定模板。

### 2.7 轮次与结束契约

将产品字段和教学行为绑定，例如：

- 中间轮是否必须留问题；
- 结束轮必须陈述；
- 是否禁止跨模块过渡；
- 输出长度和格式。

### 2.8 学生侧表达

定义自然度、适龄化、术语使用和内部语言隔离。

### 2.9 底线与优先级

用少量高价值底线约束守住知识、边界、学生输入和内部术语。不要建立无限增长的禁止清单。

## 3. 结构性规则优于零散禁止项

当输出出现问题时，优先修根因：

| 表层问题 | 常见根因 | 优先修改方向 |
|---|---|---|
| 每轮都问“你觉得呢” | Prompt 只要求提问，没有定义教学功能 | 增加问题决策原则和知识主体要求 |
| 频繁“对，……” | 承接只被定义为确认 | 定义多种承接功能和推进要求 |
| 引入阶段讲太多 | 没有前后模块边界和停点 | 重写场景职责与禁止占用项 |
| 单词知识漏讲 | 风格/互动优先级盖过输入完整性 | 明确会话级完整覆盖和优先级 |
| 学生不知道仍追问 | 没有状态判断与降难动作 | 加入最小学生输入处理规则 |
| 自问自答 | 未区分讲解设问与互动问题 | 要求互动问题置于轮末并真正停下 |
| 问题形式单一 | 只提供固定示例 | 从认知动作和知识对象定义多样性 |
| 输出平淡 | “自然”定义过弱，只有限制无正向策略 | 增加承接、节奏和具体反馈策略 |

## 4. Prompt 长度与注意力管理

项目中已经确认：把所有好规则都叠加进 Prompt，可能导致注意力稀释、规则冲突和鲁棒性下降。

### 4.1 应保留在主 Prompt 的内容

- 当前场景核心职责；
- 输入知识边界；
- 教学主线；
- 轮次契约；
- 学生输入最小处理规则；
- 有效提问原则；
- 少量底线。

### 4.2 更适合外置的内容

- 完整评测标签；
- 大量 badcase；
- 所有历史话术；
- 复杂评分表；
- 其他学科的场景规则。

### 4.3 适龄化模块的处理

若独立模块过长并与现有规则争抢注意力，应：

- 将其压缩为少量高价值原则；或
- 分流到承接、问题、例子和表达模块中。

不能为了“复用”而牺牲主 Prompt 的稳定性。

## 5. 示例的正确使用

示例可以帮助模型理解，但也容易造成高度模仿。

### 5.1 示例应展示决策，不只展示句式

除了给出一句话，还应说明它为何适用于某状态，避免模型只复制表面结构。

### 5.2 示例数量不宜过多

过多示例会让模型围绕少数形式过拟合。

### 5.3 正反例应围绕高风险点

例如：

- 已给答案后提问；
- 自问自答；
- 学生不知道时不降难；
- 结构模块变成内容复述。

### 5.4 不把测试 case 直接写进 Prompt

应提炼根因和决策原则，否则容易只修复表面 case。
## 6. 区分问题来源

问题可能来自：

- teacher Prompt；
- 场景定义缺失；
- 入参本身；
- student simulator；
- 运行环境；
- 测试脚本；
- 单次随机波动。
## 7. 选择最小有效修改

先修改结构根因，再考虑局部措辞。避免一次性重写所有模块，除非当前架构本身失效。

Prompt 写有正确原则，只能说明设计意图存在，不等于该原则已经实际控制输出。若 case 仍然违反该原则，应继续检查是否有更强的固定流程、硬约束、规则优先级或多条规则组合覆盖了它；修改时应处理真正占优势的控制机制，而不是重复叠加同义要求。

## 8. 复测原问题与回归风险

不仅要看目标 case 是否变好，还要检查：

- 讲解是否变干瘪；
- 是否漏讲输入；
- 是否产生更机械的新模板；
- 是否为了避免选择题导致问题过难；
- 是否为了消除自问自答而失去互动；
- 是否为控制边界而缺少必要解释。
## 9. 不为一个边缘 case 增加全局重规则

若问题只在极少数 case 中出现、主链路不受影响，且修复可能导致系统回归，应作为可接受残留或继续观察。
## 10. “如果……”不是通用互动公式

假设问句只是工具之一。频繁使用会造成强模板感，应根据知识对象和认知动作选择问题。
## 11. 过修复类型

### 11.1 为消除选择题，强迫全部开放提问

结果：问题变难、学生无从回答、语法教学失去必要支架。

### 11.2 为避免自问自答，删除所有提问

结果：一对一退化为单向讲解，无法读取学生状态。

### 11.3 为避免跑题，禁止任何必要补充

结果：知识缺少背景、例子和解释，讲解干瘪。

### 11.4 为提升人感，堆叠语气词和夸奖

结果：低幼、油腻、表演化，且不改善教学决策。

### 11.5 为控制长度，压缩核心知识

结果：结构化入参没有讲完整，学生只得到碎片结论。

### 11.6 为实现问题多样性，轮换问句模板

结果：句式变化但思考动作不变，机器感仍然存在。

### 11.7 为守住每轮问句结尾，答案后强行补问

结果：形成伪互动和答案泄露。

### 11.8 为修复单个 badcase，增加大量局部禁止项

结果：Prompt 规则冲突、注意力稀释、其他 case 回归。

### 11.9 把知识组织单位、学生证据单位与提问单位机械绑定

结果：模型把每个知识字段或每项学生作答证据都自动对应为一次独立提问，使原先的字段播报转化为字段抽查或逐项口试，教学仍然被清单牵引。失败的是三种单位被固定一一绑定的规则组合，不是按关系组织知识本身；关系组织仍可保留，提问只需服务当前最关键的理解缺口。

## 12. 何时应该重构

出现以下情况时，应回到场景定义或 Prompt 架构，而不是继续加规则：

- 多类问题都指向阶段职责不清；
- 输入完整性与互动要求持续冲突；
- 每次修一个问句，另一种模板马上出现；
- 学生输入处理始终不影响下一轮；
- 结尾轮和中间轮行为长期混乱；
- Prompt 已经过长，规则互相覆盖；
- 新版只在个别 case 上改善，整体稳定性下降。

重构重点通常是：

1. 重写模块职责与停点；
2. 明确知识主线与轮次拆分；
3. 将提问从形式规则改为功能决策；
4. 将承接从固定话术改为学生状态处理；
5. 删除重复、低权重和互相冲突的规则。

## 13. 新 Prompt 初版检查表

### 13.1 场景

- 是否说明当前阶段为何存在；
- 是否明确讲到哪里停；
- 是否与前后模块分工清楚。

### 13.2 知识

- 是否明确输入内容的覆盖要求；
- 是否守住事实与材料边界；
- 是否避免为生动而编造。

### 13.3 教学

- 是否给出理解路径而非知识清单；
- 是否一轮聚焦一个主要动作；
- 是否兼顾会话完整性和单轮负荷。

### 13.4 学生输入

- 是否要求先读取最近回答；
- 是否区分正确、错误、不知道和已完成目标；
- 是否会根据回答调整下一步。

### 13.5 问题

- 是否定义问题的教学功能；
- 是否避免答案泄露和自问自答；
- 是否允许按场景使用选择、定位和确认；
- 是否避免固定句式过拟合。

### 13.6 表达

- 是否适龄；
- 是否自然但不低幼；
- 是否避免内部术语；
- 是否避免固定夸奖和流程话术。

### 13.7 轮次与输出契约

- 是否正确处理最后一轮；
- 是否需要问句结尾；
- 是否禁止跨模块过渡；
- 是否遵守格式、字段和长度约束。

## 14. 修改原则

- 先修场景、主线、优先级和决策机制；
- 再修局部话术；
- 使用最小有效修改；
- 不把评测框架整段塞进 teacher Prompt；
- 不为一个 case 堆叠全局规则；
- 保留原版本已经有效的能力。
